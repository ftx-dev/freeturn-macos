# FreeTurn для macOS — дизайн клиента (этап 1)

Дата: 2026-11-14. Статус: на согласовании.

## Зачем

Нужен нативный клиент free-turn-proxy для macOS: красивый, с возможностями
Android-клиента и с гибкой маршрутизацией уровня Happ. Сейчас на маке есть только
консольный клиент, который требует `sudo`, отдельный WireGuard и ручные маршруты.

Референсы:
- ядро: `hackdiaz-dev/free-turn-proxy`, версия v4.1.5;
- Android-клиент: `hackdiaz-dev/turn-proxy-android`, версия 5.3.4;
- Happ 4.5.4 для macOS — образец маршрутизации и работы туннеля.

## Цели этапа 1

1. Системный VPN-туннель (WireGuard / AmneziaWG) поверх free-turn-proxy, провайдеры
   Relay (через звонок) и Direct — как на Android.
2. Несколько серверов в списке: добавить, клонировать, переименовать, удалить,
   выбрать активный.
3. Импорт ссылок `freeturn://`: вставка из буфера, открытие ссылки системой,
   QR с картинки или экрана, ручной ввод.
4. Раздельное туннелирование как в Happ: по приложениям, доменам, подсетям.
5. Капча: автоматическая в фоне, ручная в панели, «продвинутая».
6. Статистика, логи, иконка в строке меню, настройки приложения.
7. Живучесть: смена сети, сон и пробуждение, автоподключение.

## Не входит в этап 1

Это отдельные этапы, у каждого будет свой дизайн:
- **Этап 2:** выдача доступа другим (ссылка, QR, список пользователей, отзыв) и
  резервные копии под паролем, совместимые с Android.
- **Этап 3:** установка и управление сервером на VPS по SSH.

Не делаем вообще:
- режим локального порта для внешнего клиента (решение пользователя);
- TCP-режим проброса для Xray, профили ARQ и bond — они работают только через
  локальный порт. Ссылка с `mode: tcp` импортируется с понятным отказом;
- подписки со списком серверов;
- раздачу туннеля в локальную сеть через SOCKS5 (можно вернуть позже);
- проверку обновлений приложения — появится, когда у клиента будут свои релизы;
- то, что есть только на Android: виджет, плитка, Tasker, батарея, сезонный декор.

## Чего нельзя допустить

- Туннель «в никуда»: приложение или ядро упало, а системный туннель остался и
  интернет пропал. Движок обязан гаснуть вместе с приложением.
- Петля: трафик самого ядра к реле заворачивается обратно в туннель.
- Фоновая служба с правами администратора, через которую посторонняя программа
  может запустить свой код или перезаписать чужие файлы.
- Утечка секретов: ключи, ссылки на звонок и IP в логах при включённом приватном
  режиме.

## Ограничения

- На машине нет Xcode, только Command Line Tools (Swift 6.3) и Go 1.26.
  Сборка — через SwiftPM и скрипт, который собирает `.app`.
- Нет платного аккаунта Apple Developer: подпись ad-hoc, приложение для личного
  использования. Раздача другим потребует подписи и нотаризации — вне этапа.
- Минимальная версия macOS — 14, архитектура arm64.
- Ядро используется без правок, через его публичный пакет `mobile`.
- Лицензии: Android-клиент под GPL-3.0, sing-box под GPL-3.0. Клиент — тоже GPL-3.0.

## Варианты, которые рассматривались

| Вариант | Суть | Цена | Итог |
|---|---|---|---|
| A. Готовый движок рядом с ядром | Маршрутизацию делает Amnezia Box (сборка sing-box с AmneziaWG), ядро отдаёт ему локальный порт | Два бинарника, обновляются отдельно | **Выбран** |
| B. Один свой процесс | Ядро и движок сшиты в одну программу, как на Android | Правки внутри ядра, конфликт библиотек, ручной перенос при обновлениях | Отклонён |
| C. VPN-расширение Apple | Системный механизм VPN | Xcode, платный аккаунт; правил по приложениям для обычных программ нет | Отклонён |
| D. Свой маршрутизатор | Написать разбор трафика самим | Месяцы работы | Отклонён |

Вариант A выбран автором дизайна: пользователь оставил выбор способа за ним.
Причины: меньше всего своего сетевого кода, ядро не трогаем, маршрутизация
ведёт себя как в Happ, потому что движок тот же.

## Устройство

Три процесса:

```
┌──────────────────────── пользователь ────────────────────────┐
│  FreeTurn.app (SwiftUI)                                       │
│   • интерфейс, список серверов, правила, настройки            │
│   • окно капчи (WKWebView)                                    │
│   • собирает конфиг ядра и конфиг движка                      │
│        │ stdin/stdout, строки JSON          │ unix-сокет      │
│        ▼                                    ▼                 │
│  freeturn-core (Go)                 ┌──── root ────────────┐  │
│   • обёртка над пакетом mobile      │ freeturnd (служба)   │  │
│   • слушает UDP 127.0.0.1:<порт>    │  запускает движок    │  │
│   • сессия к реле или напрямую      │  amnezia-box         │  │
└─────────────────────────────────────┴──────────────────────┴──┘
```

Путь трафика:

```
программа → utun (движок) → правила
   ├─ через VPN  → WG/AWG внутри движка → UDP 127.0.0.1:<порт> → ядро
   │               → DTLS + обфускация → реле звонка (или напрямую) → VPS
   ├─ напрямую   → физический интерфейс
   └─ блокировать
```

### freeturn-core

Небольшая программа на Go, использует только публичный API ядра: `Start`,
`Stop`, `Reconnect`, `Wake`, `SetDNSServers`, `SetProtect`, `SetEventSink`,
`GetState`, `ConfigToArgs`, `SetStateDir`, `Version`.

- Запускается приложением как дочерний процесс, без прав администратора.
- Команды приходят строками JSON в stdin, события уходят строками JSON в stdout:
  состояние, лог, капча, счётчики.
- Закрытие stdin означает, что приложение умерло: процесс останавливает ядро и
  выходит.
- Защита от петли: через `SetProtect` каждый исходящий сокет ядра привязывается к
  физическому интерфейсу (`IP_BOUND_IF` / `IPV6_BOUND_IF`). Проверено по коду
  v4.1.5: все исходящие сокеты идут через этот хук, а локальный UDP-порт и
  страница капчи — нет, то есть остаются на loopback. Индекс интерфейса
  приложение передаёт при старте и при смене сети.
- Конфиг ядра — тот же JSON, что собирает Android (`toCoreJson`), с отличиями:
  `tunnel.mode: none`, `proxy.mode: udp`, `proxy.listen: 127.0.0.1:<свободный порт>`,
  `vk.platform: desktop`, `routes: false`.
- Client ID устройства (32 hex) создаётся один раз и хранится в приложении.

### freeturnd и движок

- Служба `launchd` с правами root. Ставится один раз из приложения по паролю
  администратора; в настройках есть «Переустановить» и «Удалить».
- Умеет три вещи: запустить движок с конфигом, остановить, отдать состояние и
  журнал движка.
- Общается через unix-сокет, доступный только пользователю, который ставил службу.
- Движок привязан к соединению: сокет закрылся — движок остановлен, туннель снят.
- Бинарник движка при установке копируется в каталог, принадлежащий root.
  Из пользовательского каталога служба ничего не запускает.
- Служба не принимает пути к файлам от клиента: журнал и кэш движка лежат в её
  собственном каталоге, эти поля конфига она выставляет сама, а чужие отвергает.
- Движок — Amnezia Box, собирается из исходников закреплённой версии (готовых
  сборок у проекта нет).

### Конфиг движка

Собирает приложение из активного сервера и профиля маршрутизации:

- вход `tun` с автоматическими маршрутами, MTU 1280 (константа, как на Android);
- точка WireGuard или AmneziaWG из конфига сервера: ключи и параметры Amnezia
  берутся из текста wg-quick, `Endpoint` заменяется на `127.0.0.1:<порт ядра>`;
- выходы: `vpn`, `direct`, `block`;
- правила маршрутизации и DNS из профиля;
- `AllowedIPs` из конфига сервера задают, какие адреса вообще попадают в туннель,
  правила профиля действуют внутри этого набора.

Сервер без конфига WireGuard (на Android это «прокси-доступ») сохраняется, но
подключиться к нему нельзя: карточка сервера просит добавить конфиг. Причина —
режима локального порта в клиенте нет.

## Маршрутизация

- Действия: через VPN, напрямую, блокировать.
- Условия правила: приложение (выбор из запущенных и установленных, по пути к
  программе), домен (точное имя, суффикс, ключевое слово, готовые списки),
  подсеть IP.
- Режим по умолчанию: «всё через VPN, кроме выбранного» или «только выбранное
  через VPN».
- Профили правил: создать, клонировать, импорт и экспорт в файл. Профиль
  привязывается к серверу или объявляется общим для всех, как на Android.
- Готовый профиль «российские сервисы напрямую» — аналог списка исключений
  Android, но по доменам и приложениям macOS.
- DNS: сервер для трафика через VPN (из конфига WG, можно заменить) и сервер для
  прямого трафика (системный); локальная сеть всегда напрямую.
- Тип туннеля: system / gvisor / mixed — только если закреплённая версия движка
  ещё поддерживает этот параметр (в новых sing-box его убирают).
- Правила меняются при остановленном подключении, либо применяются с
  переподключением по кнопке.

## Экраны

Одно окно с боковой панелью и иконка в строке меню.

```
┌────────────┬────────────────────────────────────────────┐
│ Главная    │            ( большая кнопка )              │
│ Серверы    │              Подключено                    │
│ Маршруты   │      RU-Server · Relay · 10/12 потоков     │
│ Логи       │  ↓ 4,2 МБ/с  ↑ 310 КБ/с   пинг 48 мс       │
│ Настройки  │  Принято 1,3 ГБ · Отправлено 96 МБ · 02:14 │
│            │  Маршруты: «РФ напрямую» · 14 правил       │
└────────────┴────────────────────────────────────────────┘
```

- **Главная:** кнопка подключения с состояниями (выключено, подключение, капча,
  подключено, ошибка), активный сервер с быстрой сменой, скорость, трафик, время
  сессии, потоки, пинг через туннель, активный профиль маршрутов.
- **Серверы:** список, добавление (вставить ссылку, QR, вручную), карточка
  сервера с параметрами Android: адрес, провайдер, ссылка на звонок, потоки,
  потоков на аккаунт, транспорт до реле, запасной TURN-узел, обфускация (профиль,
  ключ, пейсинг), DNS ядра, ручная капча, конфиг WireGuard (вставить или из файла).
- **Маршруты:** профили и правила.
- **Логи:** поток событий ядра и движка, фильтр по уровню, копировать, очистить,
  сохранить в файл. Файл на диске с ротацией 1 МБ.
- **Настройки:** тема, язык (русский, английский), автозапуск при входе,
  автоподключение, приватный режим, подробные логи, «продвинутая» капча, где открывать
  капчу (окно приложения или браузер), режим
  отладки (состояние ядра, версии, команда запуска), служба (состояние,
  переустановка, удаление), сброс.
- **Строка меню:** состояние цветом иконки, подключить и отключить, смена
  сервера, скорость, «Пройти проверку» при капче, открыть окно.

### Импорт

- Формат ссылки — как в ядре и на Android: `freeturn://` + base64url(JSON), `v: 1`.
- Приложение регистрирует схему `freeturn://`, поэтому ссылка открывается кликом.
- QR: картинка из файла, из буфера или снимок области экрана.
- Перед сохранением показывается панель импорта: имя, тип доступа, поле ссылки
  на звонок (обязательно для Relay, если её нет в ссылке), проверка дублей.

### Капча

- Ядро само поднимает страницу на `localhost:8765` и сообщает, когда её показать
  и когда убрать.
- Автоматическая: невидимый WKWebView, живёт только на время проверки; в
  интерфейсе статус «CAPTCHA решается…».
- Ручная, режим «в окне» (по умолчанию): отдельное окно приложения поверх остальных
  окон. Открывается само, когда ядро просит проверку, и закрывается само, как только
  она пройдена. Главное окно при этом может быть закрыто.
- Ручная, режим «в браузере»: локальная страница ядра открывается в браузере по
  умолчанию; в приложении остаётся статус и кнопка «Открыть снова».
- Режим выбирается в настройках: «Открывать капчу: в окне приложения / в браузере».
- Закрыл окно, не решив: на главной и в строке меню остаётся статус с кнопкой
  «Пройти проверку».
- Разрешён только адрес `http://localhost:8765` и `http://127.0.0.1:8765` — и для окна,
  и для браузера; в окне переходы наружу блокируются, хранилище WebView непостоянное.

Изменено 2026-11-14 по просьбе пользователя: вместо панели внутри главного окна и
уведомления — отдельное окно поверх, плюс выбор «окно или браузер».

## Живучесть

- Смена сети (NWPathMonitor): новый индекс интерфейса и DNS в ядро, затем
  `Reconnect`. Движок сам следит за интерфейсом по умолчанию.
- Пробуждение после сна дольше минуты: `Wake`.
- Ошибка ядра: подключение снимается целиком, показывается причина, автоповтора
  по кругу нет.
- Автоподключение при запуске — только если прошлую сессию пользователь не
  выключал сам.
- Приложение закрыто или упало: ядро выходит по закрытию stdin, движок — по
  закрытию сокета.

## Хранение

- Серверы, профили, настройки — JSON в `~/Library/Application Support/FreeTurn/`.
- Схема сервера повторяет Android (`ServerJson`), чтобы этап 2 мог читать и
  писать бэкапы Android без преобразований.
- Секреты (ключ обфускации, конфиг WG, ссылка на звонок) лежат в том же файле с
  правами 0600 — как на Android. Связка ключей — возможное улучшение позже.

## Обработка ошибок

- Нет службы или она не отвечает: предложение установить или переустановить.
- Движок не поднялся: текст ошибки из его журнала, ядро останавливается.
- Ядро отклонило конфиг: текст ошибки ядра рядом с кнопкой подключения.
- Ссылка не разобралась или версия не та: панель с объяснением.
- Порт капчи 8765 занят: сообщение с названием причины.

## Проверка

- Модульные тесты: разбор и сборка `freeturn://` (на векторах из тестов Android),
  разбор wg-quick, сборка конфига ядра, сборка конфига движка из правил.
- Тест протокола `freeturn-core` на ядре без сети: старт с плохим конфигом,
  остановка, закрытие stdin.
- Ручной прогон на живом сервере: Relay и Direct, WG и AWG, правило по
  приложению, правило по домену, смена Wi-Fi, сон, капча.

## Порядок работ и риски

Первым шагом идёт пробная сборка — она снимает главные риски до того, как
строится интерфейс:

1. Amnezia Box собирается из исходников и поднимает туннель на macOS 26 от root.
2. WG и AWG внутри движка работают через локальный порт ядра.
3. Привязка сокетов ядра к интерфейсу действительно уводит их мимо туннеля.
4. Правила по приложению и по домену срабатывают.

Если Amnezia Box подведёт (проект маленький, готовых сборок нет), запасной путь —
обычный sing-box: тот же конфиг, но только WireGuard, без AmneziaWG. Это решение
принимается по итогам пробной сборки и согласуется с пользователем.

Остальные риски:
- Капча проверяется только на живой ссылке на звонок. Встроенный браузер macOS —
  Safari, а ядро представляется как Chrome; расхождение может повлиять на проверку.
- Установка службы без подписи разработчика идёт через запрос пароля
  администратора; поведение на macOS 26 проверяется на пробной сборке.

## Что остаётся строителю

- Точный формат строк JSON между приложением и `freeturn-core`.
- Точный протокол сокета `freeturnd`.
- Раскладка каталогов проекта и скрипт сборки `.app`.
- Состав готового профиля «российские сервисы напрямую».
- Визуальные детали: цвета, анимация кнопки, иконка.

## Решения автора дизайна (не обсуждались с пользователем)

- Сборка только для личного использования, без подписи Apple.
- macOS 14+, только arm64.
- Ядро живёт пока живо приложение: закрыл приложение — VPN выключен.
- SOCKS5-раздача в локальную сеть не входит.
- Языки интерфейса: русский и английский.
- Секреты хранятся в файле, не в связке ключей.
- Проверки обновлений в этапе 1 нет.
- Сервер без конфига WireGuard сохраняется, но не подключается.
- Порядок этапов: клиент, затем доступ другим и бэкапы, затем VPS по SSH.
